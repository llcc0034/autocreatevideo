# 运维管理前端规范

## 适用范围与目标

本规范适用于服务器运营、CMDB、告警、工单、任务中心、配置中心、通知中心、数据报表、审计和受控终端等运维管理页面。目标是支持持续查询、对比、处理和追踪，不按营销网站、内容门户或展示型大屏设计。

## 按任务加载

先读取本节，再完整读取下表命中的章节。新增完整页面、整体改版、公共设计系统调整或同时影响多数页面职责时读取全文。

| 任务范围 | 必读章节 |
| --- | --- |
| 小型样式、间距、颜色、组件外观 | 视觉与版式；响应式与可访问性；公共实现与复用 |
| 导航、页面骨架、首页或页面归属 | 开发前检查；信息架构与导航；页面类型与职责；文案、语义与帮助 |
| 筛选、列表、分页或详情 | 文案、语义与帮助；数据展示职责与页面归属；查询与筛选；汇总、表格、图表与下钻；页面状态、请求与浏览器缓存；数据质量与错误反馈 |
| KPI、趋势、分布、Top N、下钻或导出 | 文案、语义与帮助；数据展示职责与页面归属；汇总、表格、图表与下钻；数据质量与错误反馈 |
| 页面请求、Tab 状态或浏览器缓存 | 页面状态、请求与浏览器缓存；数据质量与错误反馈；公共实现与复用 |
| 任务中心、配置中心或通知中心页面 | 页面类型与职责；操作安全、任务、配置和通知；页面状态、请求与浏览器缓存；数据质量与错误反馈 |
| 处理工作台、受控终端或命令交互 | 操作安全、任务、配置和通知；运维处理工作台与终端；页面状态、请求与浏览器缓存；响应式与可访问性 |
| 公共组件、设计变量或前端基础设施 | 开发前检查；公共实现与复用；响应式与可访问性；受影响组件对应的业务章节 |

## 开发前检查

- 先检查是否已有统一页面骨架、导航配置、样式变量、查询面板、表格、分页、弹框、状态提示、请求和缓存工具；已有设计系统时优先沿用。
- 同类页面各自维护导航、筛选、多选、按钮、表格或弹框时，应先收敛公共规格，再新增页面。
- 开发前明确页面类型、核心用户、主要动作、数据来源、刷新方式、缓存范围、错误状态、数据质量和审计要求。
- 功能、接口、任务、配置或数据口径变化时，同步检查页面入口、提示、状态、下钻和导出。

## 信息架构与导航

- 全局导航按稳定业务域分组，例如资源管理、告警处理、工单处理、工具、数据与报表、配置管理；不得因开发方便混放无关功能。
- 通知中心和配置中心是同级独立页面，可共同位于“配置管理”分组；通知规则、渠道和发送历史不得分散在业务菜单。
- 导航由一个权威配置维护。新增、改名或删除页面只修改一个入口，页面不得复制菜单结构。
- 导航明确展示当前页面和展开分组，支持键盘操作，并使用 `aria-current`、`aria-expanded` 等属性表达状态。
- 一级导航负责业务域，二级导航负责独立页面；Tab 只用于共享上下文且职责高度相关的视图。
- 首页直接展示运行概览、待处理事项和关键异常，不制作营销式落地页、超大 Hero、功能介绍卡或纯装饰首屏。
- 页面标题区保持紧凑，只放页面名称、必要数据时间或状态摘要和少量全局动作；长说明进入帮助弹框或正式文档。

推荐桌面骨架：

```text
┌──────────────┬────────────────────────────────────────────┐
│ 全局侧边导航 │ 页面标题 / 数据时间 / 必要全局操作          │
│              ├────────────────────────────────────────────┤
│              │ 查询筛选或上下文摘要                        │
│              ├────────────────────────────────────────────┤
│              │ 汇总 / 趋势 / 主表格 / 工作台               │
│              │ 页面内部按职责决定独立滚动区域               │
└──────────────┴────────────────────────────────────────────┘
```

## 页面类型与职责

| 页面类型 | 最低结构 | 主要职责 | 不承担职责 |
| --- | --- | --- | --- |
| 运行概览 | 数据时间、核心汇总、Top N 异常或分布、待处理入口 | 快速判断状态并进入全量页面 | 完整明细查询或高风险操作 |
| 查询清单 | 折叠筛选、结果摘要、分页表格、详情、导出 | 查询、筛选、比较当前事实 | 同步、补跑或数据重建 |
| 报表分析 | 范围与粒度、汇总、趋势、分布、下钻、导出 | 展示明确口径的聚合结果 | 展示层重定义指标或静默补数据 |
| 任务中心 | 任务说明、参数、启动、进度、结果、历史 | 手动运行任务并观察状态 | 依赖命令行作为日常入口 |
| 配置中心 | 分类导航、配置表单、影响、校验、保存状态 | 维护运行期策略 | 展示普通只读业务数据 |
| 通知中心 | 场景规则、渠道、接收人来源、测试、结果和历史 | 管理通知策略并追踪发送 | 在业务页重复维护规则和渠道 |
| 处理工作台 | 待办、工作项标签、主操作区、记录和审计 | 连续处理告警、工单或设备问题 | 平铺辅助信息挤压主区 |
| 历史与审计 | 筛选、时间线或表格、详情、导出 | 查询跨对象操作事实 | 修改或删除历史事实 |
| 数据同步与后台管理 | 数据源、批次、进度、覆盖率、异常、manifest、重跑 | 排查数据链路和同步质量 | 承载业务清单、KPI 或处置动作 |

## 视觉与版式

- 运维后台应安静、克制、信息密度适中，使用中性背景、清晰边界和有限强调色；不使用大面积渐变、装饰光斑、渐变球、插画背景或单色铺满页面。
- 色彩主要表达成功、告警、危险、处理中、禁用和信息状态；同一状态跨页面使用相同颜色与文案，且不能只依赖颜色。
- 页面优先使用无框布局、分隔线或全宽区域；卡片仅用于独立汇总、重复项目、弹框或确需边界的工具，不层层嵌套。
- 卡片、输入框、按钮和弹框圆角默认不超过 `8px`；已有设计系统另有明确规范时从其规定，不使用过度胶囊化组件。
- 标题和辅助文字按层级递减，紧凑面板不使用 Hero 大字，不使用随视口变化的字体大小，字间距统一为 `0`。
- 每页只保留一个页面主标题。面包屑、Tab、卡片和表格标题不得重复完整页名。
- 汇总负责快速判断，图表负责趋势或分布，表格负责明细；同一数据不得在多个区域无差别重复。重复时必须表达不同范围、时间或聚合层级。
- 页面区块只有在提供新判断、操作或明细时才存在，删除仅重复数字、说明或状态的装饰区域。
- 数据时间、查询范围和数据来源应有一个主要展示位置；区块口径不同才就近补充。
- 使用稳定间距、网格、最小和最大宽度及 `aspect-ratio`，避免图表、计数和加载状态引发布局跳动。
- 长 SN、IP、路径、错误信息和连续单词必须支持换行、截断加 Tooltip 或受控横向滚动，不能与相邻组件重叠。
- 优先使用项目已有图标库。常见关闭、刷新、下载、展开等动作使用图标按钮和 Tooltip，不重复手绘 SVG 或用大圆角文字按钮替代。

## 文案、语义与帮助

- 页面应让用户无需查看代码即可理解业务对象、数据范围、核心状态和可执行动作；名称优先使用业务语义，不暴露内部实现名。
- 不单独使用“总数”“当前”“最新”“变化”“异常”“已处理”“完成”或“时间”等歧义名称，应补充对象、范围、时间边界或状态条件。
- 影响当前判断的对象、单位、时间和数据质量直接展示；默认值用辅助文字；定义、公式、来源和示例使用信息图标、Tooltip 或 Popover；复杂说明进入帮助弹框或权威文档。
- 不在业务区平铺大段功能介绍、教程、视觉说明或快捷键说明；帮助信息应就近、简短、按需展开。
- KPI 明确名称、值、单位、数据时间或查询范围；比率和平均值说明分子、分母、聚合方式及无分母语义。
- 时间字段说明时区、边界和业务含义，区分事件、创建、更新、快照、同步和计算时间。
- 表格列、筛选项、图例和下钻使用一致名称、单位和口径；专业缩写、外部字段和内部状态码首次出现时提供中文含义或映射。
- 筛选控件必须有稳定 Label，占位符不能替代 Label；“全部”、空值、默认值、多选并集或交集及级联含义必须明确。
- 按钮和菜单说明动作对象和主要影响，不只写“执行”“处理”“确认”“更新”；禁用原因不明显时应可查看。
- 图标、颜色、符号或简写必须提供 Tooltip 和 `aria-label`；关键含义不能只靠悬停，键盘和触摸设备也必须可访问。
- `0`、空值、未配置、未同步、字段缺失、无权限、无法计算和查询失败使用不同状态与文案，不能统一替换为 `-`、“无”或“数据异常”。
- 动态指标、配置枚举、状态和规则的名称、说明、单位、默认值和公式应来自后端或配置中心的同一元数据，页面不维护第二份常量。
- 项目统一维护业务术语、状态、指标说明和空值文案；调整时同步更新页面、API、配置、测试和文档。

## 数据展示职责与页面归属

- 页面内容按业务事实、变化事实、数据质量摘要、同步过程、原始证据和操作审计分层，不能因为接口返回字段就全部平铺。
- 业务页面展示完成业务判断所需的当前事实、范围、核心状态、变化结果和简明质量状态；原始响应、映射诊断、异常原文、堆栈、缺失样例和重试日志进入同步历史、任务中心或后台管理。
- 数据源问题影响业务结论时，业务页持续显示“同步失败”“数据截至某时”“覆盖率不足”等简明状态，并提供查看详情入口；不能完全隐藏，也不能在主区展开完整技术诊断。
- 数据不足以支持指标或状态时，应停止或降级计算并标记“无法判断”或“部分数据”，不能继续显示看似正常的结果。

| 数据内容 | 主要位置 | 业务页面方式 |
| --- | --- | --- |
| 当前清单、状态和汇总 | 对应清单、概览或处理页 | 直接展示并标明时间和范围 |
| 新增、移除、变更及前后值 | 变化视图或下钻 | 展示结论、数量和可追溯明细 |
| 覆盖率、陈旧时间、完整性 | 业务摘要 + 同步详情 | 业务页简明提示，详情页解释原因 |
| 原始响应、异常样例、任务日志、重试 | 同步历史、任务中心或后台管理 | 业务页只显示状态和跳转 |
| 领取、配置、命令、重跑等操作 | 对象时间线或统一审计 | 按需查看，不与源数据异常混合 |

## 查询与筛选

- 选项查询页面使用统一可折叠筛选面板，标题展示已选条件数，标签、控件高度、列宽、间距和按钮位置保持一致。
- 普通枚举使用下拉；多选维度支持搜索、已选数、全选、清空和候选滚动；批量 SN、IP 或工单号使用可折叠批量输入区。
- 二元条件使用开关、复选框或分段控件；数值范围使用成对输入、步进器或滑块，不把所有条件做成自由文本。
- 主动作为“查询”，旁边提供“清空筛选”；清空只恢复条件，不隐式同步、重建或修改数据。
- 选择筛选项不自动触发高成本查询；轻量联动可按需加载，但有加载和失败状态。
- 进入后自然期待看到当前清单或概览的页面可以自动加载；报表、历史大范围查询和高成本聚合必须显式触发。
- 日期范围、统计粒度、数据时间、时区和区间边界在页面明确展示；报表的日期范围与统计粒度分开。
- 筛选当前结果与重新生成基准数据必须使用不同动作和文案。
- 状态、业务范围、SID、阈值、节点和筛选规则应进入配置中心；页面不得写死第二份。

## 汇总、表格、图表与下钻

- 汇总卡只放快速判断所需核心指标，数量克制，并标明单位、数据时间和必要质量状态。
- 概览可展示 Top N，但必须标明“Top N”、排序依据、完整总数和数据范围，并提供全量入口。
- 分布报表、分析、详情、下钻和查询清单不得静默截断为固定前几项；当前筛选下的全部数据必须可访问。
- 全量访问不等于一次响应或一次 DOM 加载全部记录。明细使用服务端分页、游标、虚拟滚动或按需加载；多分类图表使用缩放、滚动轴、图例分页或配套全量表格。
- 全量页显示总数、已加载范围和分页或滚动状态；“其他”聚合必须可查看其中全部类别和明细。
- 表格是运维清单主要载体，应有稳定列宽、清晰表头、分页、横向滚动，必要时固定表头和关键列；不得一次渲染数千条。
- 首屏只展示高频判断字段，低频原始字段进入详情弹框、抽屉或展开区。
- 状态列使用文字、语义色和必要说明；`-`、空白和“无”只用于确认数据确实不存在，缺失、不完整、无法判断和失败应显示不同状态并可查看原因。
- 图表与表格、下钻使用同一口径，标题、图例、单位、范围和 Tooltip 完整；只有一个点时不绘制误导性折线。
- 趋势按范围支持日、周、月、年等粒度，每个周期点携带开始和结束边界并可按周期下钻。
- 下钻使用弹框、抽屉或独立详情页，不在主页面底部长期开巨大明细。
- 可解释的 KPI、趋势点、分布项和汇总值应支持下钻，下钻数量与入口汇总一致。
- 下钻默认提供当前范围的完整当前清单，不能只显示聚合数字或只列变化记录。
- 包含新增、减少、消失、恢复、关闭、转入、转出或净变化时，下钻必须分别提供“当前清单”和“变化明细”，不能混为一张无类型表。
- 变化明细至少包括变化类型、业务主键、变化时间或周期、对比基准、旧值、新值、变化字段和当前是否仍存在；不适用与数据缺失必须区分。
- 当前清单数量、变化数量、净变化公式和入口汇总必须一致；当前总量不能简单等同变化量之和。
- 没有基线或基线不完整时，当前清单仍可展示，但变化视图标记“无可对比基准”或具体质量原因，不能把空变化写成“无变化”。
- 导出按当前查询、周期和下钻条件重新获取完整数据，不能只导出当前页或首屏；当前清单和变化明细分别标识或提供独立导出入口。

## 页面状态、请求与浏览器缓存

- 页面必须具备加载中、成功、空数据、部分数据、失败和权限不足状态，不能只记录控制台或留空。
- 请求失败时保留筛选和已成功结果，并显示失败原因与重试入口；不能用旧缓存伪装新查询成功。
- 不同业务域、Tab 或报表类型独立保存筛选、日期、粒度、分页、结果和加载状态，不能串数据。
- 站内菜单或 Tab 切换可恢复当前会话结果并避免重复请求；用户主动刷新 URL 时，按页面约定清理会话缓存并重新查询或回到待查询状态。
- 小型状态可用 `sessionStorage`，大结果可用 IndexedDB 或框架缓存；键包含页面、业务域和必要查询口径。
- 缓存只优化交互，不改变事实来源、统计口径和同步状态；恢复时同时显示数据时间和陈旧状态。
- 页面初始化不请求所有隐藏 Tab，只加载当前视图，其他视图首次打开时加载。
- 快速重复查询时禁用重复提交、取消过期请求或使用请求序号丢弃旧响应，避免旧响应覆盖新结果。

## 操作安全、任务、配置和通知

- 查询、同步、补跑、重建、导出、配置保存和终端命令使用不同操作层级，高风险动作不能与普通查询使用相同主按钮样式。
- 删除、覆盖、清空、抢占、重新执行和影响大量数据的动作必须二次确认，说明对象、范围和不可逆后果。
- 手动同步、补跑和分析任务进入任务中心，展示参数、进度、成功量、失败量、异常样例、开始结束时间和日志入口。
- 任务启动后按钮进入禁用或运行状态防止重复提交；长任务不能用短暂 Toast 作为唯一反馈。
- 配置中心按业务域分类，展示用途、默认值、范围、生效时机、读取方和影响；保存前做结构与业务校验，失败不能局部静默生效。
- 通知中心与配置中心同级，统一管理规则、渠道、测试发送和历史；业务页只显示状态和跳转，不维护第二份通知配置。
- 高风险配置和操作记录处理人、时间、来源 IP、对象、前后值或参数、结果和错误，并提供正式审计查询入口。
- 只有后端明确完成后才能显示成功；失败、部分成功或审计失败不能显示模拟成功。

## 运维处理工作台与终端

- 终端、日志流、命令输出或主处理界面占据最大可视区域，辅助信息压缩为摘要条、侧栏、标签或弹框。
- 待办与主工作区在桌面端独立滚动，页面滚动不能使左侧待办消失；终端和输出区填满剩余高度。
- 已领取或打开的工作项使用标签切换，每个标签独立保存会话、输出和上下文；支持关闭、释放、重新加入和有审计的抢占。
- 高频只读命令使用紧凑图标或短文本按钮并支持横向滚动与 Tooltip；低频工具进入分类弹框或命令选择器。
- 执行历史、处理记录、硬件工具和新增记录通过弹框或抽屉按需打开，不长期挤占主区。
- 终端显示连接中、已连接、已断开、超时和失败状态，支持超时退出与手动重连；不得用模拟输出掩盖失败。
- 自由输入、命令白名单、目标选择、凭据获取和管理机跳转受权限和审计控制；敏感凭据不得回显或进入终端日志。

## 数据质量与错误反馈

- 页面明确展示数据来源、数据时间和完整性，例如完整、部分、缺失、陈旧和无法判断。
- 核心字段缺失、覆盖不完整、任务失败或配置加载失败使用持续可见状态条或错误区，不能只显示几秒 Toast。
- 空状态区分查询结果为 0、尚未查询、没有基线、尚未同步、数据不完整、无权限和查询失败。
- 页面不得通过默认值、临时拼接其他来源、过滤异常记录或替换文案掩盖数据问题。
- 面向用户的错误说明失败动作和下一步；堆栈进入日志或审计，不暴露敏感请求、凭据或完整内部异常。

## 响应式与可访问性

- 桌面端优先高信息密度和重复操作效率；移动端筛选网格改单列，表格使用受控横向滚动或关键字段列表，不强行压缩全部列。
- 固定侧栏、终端、工具栏、计数器和表格定义稳定尺寸与响应式约束，避免重叠和溢出。
- 按钮和输入有可见焦点；表单控件有 Label，图标按钮有 `aria-label` 或 Tooltip，弹框支持键盘关闭和焦点管理。
- 交互控件可点击高度通常不低于 `36px`，移动端按需要提高；禁用、悬停和加载状态均可辨识。
- 颜色对比满足阅读，状态不只依赖红绿；图表同时使用文字、图例、线型或标记。
- 常用桌面、窄屏和移动视口下，标题、按钮、筛选、表格、弹框和终端不得出现失控截断、遮挡或不可达操作区。

## 公共实现与复用

- 全局导航、设计变量、按钮、筛选面板、多选、表格、分页、弹框、Tooltip、Popover、指标说明、状态条、Toast、缓存和请求错误处理应沉淀为公共组件或模块。
- 页面只保留业务差异和必要布局微调，不复制整套公共 CSS 或 JavaScript 后各自修改。
- 颜色、圆角、阴影、间距、控件高度、表格密度和断点使用统一变量；修改公共规格时检查全部使用页面。
- 已有图标库、组件库、图表库和状态方案时优先复用，无明确必要不新增第二套。
- 新页面复用最接近的现有结构，同时检查查询、缓存、下钻、导出、错误状态和移动端行为，不能只复制静态视觉。
