# 运行环境与服务管理规范

## 适用范围

涉及可运行服务、启动脚本、部署、本机或内网访问、端口、运行时依赖、外部必需服务、数据库连接和日志时，必须使用本规范。

按项目真实交付形态应用：长期运行的网络服务读取服务管理、访问入口和状态输出规则；静态构建、CLI、SDK、批任务、移动端、桌面端、嵌入式或固件项目只执行与其正式构建、运行、发布、设备或任务入口相关的条目，不为满足本文件额外创建常驻服务、页面或数据库。

## 业务入口与运维入口边界

- 服务启动、停止、重启、状态检查、环境初始化、Schema 变更和一次性数据修复属于开发或运维入口。
- 面向业务终端用户且项目已有产品或管理入口时，定时任务手动执行、数据补跑、快照同步、分析、事件重建、导出、上传等日常业务操作必须通过正式页面和 API 提供。
- CLI、SDK、批处理、基础设施自动化、移动或设备项目可以使用项目声明的正式命令、库导出、任务、构建、发布、烧录或诊断入口；不得再新增绕过该权威入口的调试旁路。
- 已有命令行入口被页面或正式 API 覆盖后，应删除或收敛到正式入口；确需保留的开发或运维工具必须标明用途、适用环境和禁止作为日常业务入口。

## 权威服务管理入口

- 项目包含需要持续运行和管理的服务时，应提供一个权威快速启动或服务管理脚本，至少支持 `start`、`stop`、`restart`、`status`；一次性命令、静态构建、库调用、批任务和固件不机械套用服务生命周期命令。
- README、运维文档和实际交付只能引用该入口，不维护第二套启动命令或启动脚本。
- 脚本必须可重复执行，正确处理已启动进程、失效 PID、端口占用、异常退出和日志路径；重复执行不能产生多个无人管理的服务进程。
- PID、端口和进程校验必须关联到实际服务，不能仅因 PID 文件存在就判断服务正常。
- `stop` 和 `restart` 应有明确超时与失败反馈，不能静默遗留进程；不得用宽泛进程匹配误杀其他服务。

## 访问入口与网络配置

本节只适用于需要通过 HTTP、WebSocket、RPC 或其他网络协议持续提供访问的服务；不适用于纯静态产物、库、离线命令、批任务或仅通过设备链路运行的程序。

- 内网或团队共享项目应支持 `localhost`、稳定本地域名（如 `<hostname>.local` 或配置的内网域名）和当前 IP 访问，除非存在明确安全限制。
- 服务绑定应覆盖预期用户网络，不得仅绑定 `127.0.0.1` 后把不可达地址描述为可用。
- 启动脚本不得写死经常变化的本机 IP；应自动识别主机名、本地域名和可用 IP。
- 应同时检查绑定地址、域名解析、允许主机、CORS、Cookie、反向代理和 WebSocket 等相关配置是否支持实际入口。
- 启动成功后只能输出经过验证或明确标注状态的 URL；某个入口不可用时应单独说明原因。

## 启动前自检

启动前至少检查：

- 运行时、版本和架构是否符合项目声明。
- 包管理器是否存在，锁文件和声明依赖是否一致，必需依赖能否加载。
- 必需环境变量是否存在，配置格式、枚举和路径是否合法；不得打印敏感值。
- 日志、上传、缓存、PID、临时文件等必需目录是否存在并可写。
- 目标端口是否可用，现有占用是否属于当前服务。
- 外部必需服务是否可连接；必需依赖失败应阻止启动，可选依赖失败应明确降级范围。
- 权威 Schema 或迁移版本是否与代码期望一致。

## 数据库自检

只有数据库属于当前运行入口的必需依赖时才执行本节；不涉及数据库的项目明确记为“不适用”，不得为了通过自检临时引入数据库。

数据库检查至少覆盖：

- 驱动或客户端依赖是否存在并可加载。
- 数据库服务状态，以及 Socket 或 TCP 地址是否可达。
- 认证是否成功，目标数据库是否存在且账号具备所需权限。
- 权威 Schema、迁移版本、关键表和必要索引是否就绪。
- 新建开发库只能通过项目声明的权威 Schema 或迁移入口初始化。

数据库不可用、认证失败或 Schema 不匹配时必须阻止依赖数据库的服务启动；不得静默切换到本地文件、内存数据、过期快照或其他数据库并伪装正常。

## 自动修复边界

- 可自动修复的本地问题必须满足：结果可确定、无破坏、可重复执行，并且修复方式已由项目声明。
- 可自动处理的典型事项包括创建必需目录、清理失效 PID、通过项目包管理器补齐声明依赖、在全新开发库中调用权威入口初始化结构、按已声明方式启动本地依赖服务。
- 生产数据变更、密钥生成、账号权限修改、系统级软件安装、覆盖已有数据库和不可逆迁移不属于静默自动修复范围。
- 每项修复必须记录原因、执行动作和结果，修复完成后重新执行对应检查。
- 无法自动解决时，以非零状态退出并列出阻断项、原因、建议动作和日志位置；不得吞掉错误或只输出“启动失败”。

## 启动结果与状态输出

长期运行服务按下列内容输出；CLI、构建、批任务、移动或设备流程应改为输出对应命令退出状态、产物或任务 ID、目标环境或设备、结果位置和失败原因，不伪造 PID、URL 或数据库状态。

启动成功后至少输出：

- 服务名称、进程或 PID、实际绑定地址和端口。
- 已验证的本机地址、本地域名地址和 IP 地址，以及不可用入口。
- 数据库连接和 Schema 状态。
- 依赖自检摘要、可选依赖的降级状态和已执行的自动修复。
- 应用日志、启动日志和错误日志位置。

`status` 应区分运行正常、进程存在但健康检查失败、PID 失效、端口被其他进程占用和服务未启动，不能统一显示为“已启动”或“已停止”。

## 文档同步

- 权威启动入口、配置要求、访问方式、依赖服务、日志位置和故障处理应进入 README 或正式运维文档。
- 启动方式、绑定地址、数据库依赖或自动修复范围变化时，应同步更新服务脚本、配置样例、运维文档和验证清单。
- 文档不得展示未经验证的访问地址，也不得记录密钥、密码或真实敏感配置。
