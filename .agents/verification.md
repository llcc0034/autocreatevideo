# 验证与交付规范

## 使用方式

- 交付前按实际影响范围读取并执行对应章节，不要求无条件执行与任务无关的全量验证。
- 验证应覆盖最可能受影响的真实主路径，不能只做静态检查后声称运行正常。
- 无法执行的验证必须在交付说明中写明原因、未覆盖范围和剩余风险。
- 验证失败时先判断是实现问题、环境问题还是依赖缺失；不得隐藏失败、降低断言或删除测试来制造通过结果。
- 当前按业务模块独立交付：验证本模块的页面/API/数据和必要依赖，已通过模块不因尚未完成全平台而撤销验收。生产级容量、SLA、完整灾备及目标数据库认证仅在明确纳入时执行；不把这些延期项变成日常开发门禁。

## 按任务加载

始终读取“使用方式”“通用完成条件”和“交付说明最低内容”，再读取下表命中的验证章节。跨范围任务读取章节并集。

| 改动范围 | 必读验证章节 |
| --- | --- |
| 删除旧入口、重命名、兼容清理 | 残留与一致性检查 |
| 项目初始化、目录移动或模块重组 | 项目目录结构验证；残留与一致性检查 |
| 安装、升级或切换固定场景规范包 | 项目场景规范验证 |
| 普通算法、CLI、SDK、文件处理或非查询代码 | 代码与后端验证中的通用代码条目；涉及旧入口时补读“残留与一致性检查” |
| 服务 API 或后端业务逻辑 | 代码与后端验证中的通用代码与接口条目；涉及旧入口时补读“残留与一致性检查” |
| 数据库查询、列表、分页、聚合或高频接口 | 代码与后端验证全文 |
| Schema、字段、索引、文件存储 | 数据结构与存储验证；代码与后端验证 |
| 同步、补数、重算或数据修复 | 同步、修复与派生结果验证；数据结构与存储验证 |
| 配置中心或通知中心 | 配置中心与通知中心验证 |
| 页面、交互、样式、图表或浏览器状态 | 前端浏览器验证 |
| 任务中心、高风险操作或终端 | 任务、操作与终端验证；涉及页面时补读“前端浏览器验证” |
| 启动脚本、环境、数据库启动依赖或网络访问 | 运行环境与服务管理验证 |
| API 文档或其他正式文档 | API 与文档验证 |
| 新增、迁移或调整结构化知识库 | 残留与一致性检查；API 与文档验证；项目目录结构验证 |

## 通用完成条件

- 代码、页面、API、Schema、配置、测试和文档指向同一主路径。
- 已删除功能没有遗留按钮、路由、函数、接口别名、字段别名、配置键、测试口径或数据样例。
- 没有静默回退到旧缓存、本地文件、内存数据、默认值或其他事实来源。
- 页面和 API 的成功状态来自真实后端结果，不存在模拟成功或仅 Toast 成功。
- 已验证、未验证、部分通过和环境受限状态在交付说明中明确区分。

## 残留与一致性检查

- 搜索旧功能名、旧路由、旧接口、旧表名、旧字段、旧配置键、旧按钮文案和旧文件路径。
- 覆盖代码、页面、测试、文档、配置样例和数据样例，不只搜索当前修改目录。
- 检查是否形成两个 Schema 入口、两个服务启动入口、两个导航配置、两个事实来源或两份同职责文档。
- 检查 README、文档索引、页面链接和 API 文档中的路径是否仍存在。
- 如果确有经用户批准的短期兼容，验证废弃标识、责任人、移除时间和调用监控是否完整。

## 项目目录结构验证

- 根 `AGENTS.md` 的项目事实记录了自动识别的项目类型、主目录档案、必要附加档案、主要目录和权威命令；无法验证项明确标记待确认。
- 目录结构符合 `.agents/project-structure.md` 的通用底线及所选档案；框架约定与模板存在差异时已记录采用框架约定的证据。
- 同一职责没有并存的 `src`/`app`、`pages`/`views`、`utils`/`helpers`、`migration`/`migrations` 等重复主目录。
- 源码、测试、文档、迁移、脚本、配置、生成物和运行期可变文件边界清楚，根目录没有临时脚本、数据导出、日志或调试文件散落。
- 移动目录后，导入路径、构建配置、启动入口、容器配置、CI、测试发现、静态资源引用和文档链接全部更新。
- 旧目录、旧路径别名、软链接、复制文件和兼容导入已清理；存在外部契约时按已确认的迁移和下线方案验证。
- 构建产物、覆盖率、缓存、日志、PID、上传和本地数据库等可变内容进入统一忽略或外部存储策略，没有提交为源码。

## 项目场景规范验证

- 根 `AGENTS.md` 只包含项目事实、全局硬约束、专项路由和最小流程，建议保持在 `8 KiB` 内且不得超过 `12 KiB`。
- 根文件引用的 `.agents/*.md` 全部存在且非空；未命中的专项不要求读取，不能为“保险”一次加载整套规则。
- `.agents/scenario.md` 中的场景 ID、名称和规则与根“项目事实”一致；一个目标项目只使用一个场景，不组合多个场景或保留第二份场景正文。
- `project-structure`、`runtime`、`data-backend`、`api-docs`、`verification` 和 `multi-agent` 六个公共专项齐全；前端专项只保留该规范包实际选择的规则族，无界面场景可以不包含前端专项。
- 规范包不包含构建器、catalog、模板检查器、模板 README、知识条目或真实 `.env`；目标项目不在运行期生成、拼接或切换规则。
- 安装或升级后，技术栈、主要目录、启动入口、Schema、测试命令和正式文档位置等项目事实保持真实且不重复；固定场景和规范版本恢复为权威值。
- 所选场景必须与项目主要用户、核心流程和主要风险一致；切换场景时替换整个规范包，并重新核对项目事实、信息架构、数据、权限、通知、指标和验收。

## 代码与后端验证

- 至少执行与改动语言和模块匹配的语法检查、类型检查、单元测试或关键路径测试。
- 检查本次改动的输入、输出、边界、错误、权限和副作用，确认没有吞错、模拟成功、重复主路径或未声明降级。
- 仅新增或修改数据库查询、列表、聚合或排序时检查真实 SQL 和 `EXPLAIN`，记录使用索引、扫描行数、临时表、排序和回表情况。
- 仅涉及数据库列表或关联读取时检查未使用 `SELECT *` 带出大字段、不存在 N+1，分页和排序键稳定。
- 仅涉及分页或同步 JSON 列表接口时验证普通分页默认不超过 `50`、单次上限不超过 `200`，普通 JSON 优先小于 `1 MiB` 且不超过 `5 MiB`。
- 仅涉及高频 API、页面首屏或复杂同步报表时验证 `2s`、`3s`、`5s` 的相应目标；无法完成性能实测时说明未验证。
- 涉及服务或业务接口时，检查业务错误、权限不足、空数据、部分成功和外部依赖失败均有明确状态，且未写入正常缓存。

## 数据结构与存储验证

- 验证权威 Schema 或迁移能从预期初始状态建立目标结构，且不存在第二套建表入口。
- 检查主键、业务唯一性、幂等键、外键或关联字段和必要索引。
- 检查普通索引字符串长度、重复或前缀重叠索引，以及高频写入表二级索引数量；超过 `8` 个时必须有证据。
- 验证字段类型、单位、枚举、空值、时间口径和来源明确；列表主表保持窄表。
- 验证字段实际载荷与Schema、应用配置和接口上限一致；普通高频字段避免携带大正文，二进制使用正式文件存储，不机械对所有字段施加 `64 KiB` 或据此恢复已取消的存储重构。
- 验证 payload 有 schema 版本、来源、字节大小、checksum 和写入上限；稳定查询字段已拆出。
- 验证文件 manifest 包含业务键、存储后端、object key、大小、类型、checksum、schema 版本、来源、批次、时间和状态。
- 检查数据库标准化事实与原始文件职责单一，普通页面不扫描目录、下载冷文件或实时请求外部系统。
- 清理开发测试数据时核对具体对象、关联项和共享文件，报告删除结果及是否可恢复；不要求外部费用对账、历史审计留存或兼容读取。保留/归档/完整恢复只验证本次明确纳入范围。

## 同步、修复与派生结果验证

- 使用真实或具有代表性的全量、增量、空结果、部分结果、核心字段缺失、重复、乱序、迟到和删除样本验证。
- 验证同步批次记录 run_id、范围、数量、checksum 或版本、配置 hash、状态、错误和异常样例。
- 验证全量同步不会用空、部分或明显异常结果覆盖最后成功事实。
- 验证增量水位、重叠窗口、幂等、任务锁、检查点和重试不会产生重复事实或相互覆盖。
- 验证 staging、完整性校验、事务或原子切换、派生结果、manifest、版本发布和缓存失效的顺序正确。
- 验证上游核心元数据或配置变化会触发显式重算或版本更新，查询层没有临时拼接其他来源。
- 数据修复后对账源数据、标准化事实、派生结果、查询、导出和页面；同一批次重跑结果应稳定。
- 调整同步频率时验证最大允许陈旧时间、外部接口压力、数据库写入、文件数、索引增长、备份、保留和归档同步调整。

## 配置中心与通知中心验证

- 验证公共配置只有一个权威键、数据对象、保存 API 和页面入口，业务模块无双写、双读或隐藏默认值。
- 验证默认值、范围、空值语义、生效时机、读取方和影响与页面、API、代码和文档一致。
- 验证配置加载、格式和保存失败会阻止错误配置生效，并显示真实错误。
- 验证通知中心与配置中心同级，业务页没有重复规则或渠道配置。
- 验证通知规则保存、测试发送、接收人解析、唯一或幂等标识、去重、重试、失败反馈和发送历史。
- 验证密钥、Webhook、Token 和收件人敏感信息没有进入前端、普通日志、审计正文或文档。

## 前端浏览器验证

涉及布局、交互或样式时，先执行当前规范包中实际存在的 `frontend-*.md` 规则族，再使用真实浏览器检查关键流程，并覆盖项目约定的主要终端与视口。

至少验证：

- 主导航、当前页面、返回路径、深链或主要流程符合对应终端约定，键盘、触摸和焦点行为可用。
- 首次加载、刷新、前后台或页面恢复、重复请求取消、缓存数据时间和账号或视图状态隔离。
- 加载、成功、空结果、未查询、离线或未同步、部分数据、无权限、失败和数据陈旧等实际状态。
- 表单、详情、搜索、筛选、分页、上传、下载、弹框、抽屉或系统权限等本次受影响交互。
- 页面名称、字段、指标、金额、状态、单位、时区、范围、数据来源和计算口径无歧义；汇总、明细与导出能够对账。
- 隐藏视图、大结果、历史、媒体和低频详情按需加载，不一次渲染不可控数据或资源。
- 主要桌面、窄屏、移动或真实设备场景不存在失控截断、重叠、横向滚动失控、固定区遮挡或操作不可达。
- 控制台、设备日志和网络请求无非预期错误、重复写入和敏感信息泄露；错误恢复路径真实可用。

无法完成浏览器或目标设备验证时，应明确未验证的终端、视口、交互和风险，不能只用代码阅读替代实际体验验收。

## 任务、操作与终端验证

- 对已有产品页面或管理入口的业务系统，验证面向业务使用者的手动操作可通过正式页面和 API 完成，不依赖旁路命令行。
- 对 CLI、SDK、批任务、基础设施、移动端或设备项目，验证其正式命令、库 API、任务、构建、发布、烧录或诊断入口唯一且可追踪，不依赖调试旁路。
- 验证任务参数、启动、进度、成功量、失败量、异常样例、开始结束时间、日志和历史可查询。
- 验证重复提交被阻止，高风险覆盖、删除、清空、抢占和重跑具有包含对象与范围的确认。
- 验证接口失败、部分成功和附加记录失败按实际阶段展示，不伪造成功，也不将已经完成的业务误报为未执行而诱导重试。
- 终端验证连接中、成功、断开、超时、失败、手动重连、权限、白名单、审计和凭据不回显。

## 运行环境与服务管理验证

- 从服务完全停止状态依次验证 `start`、`status`、`restart`、`stop`，并重复执行确认幂等。
- 验证已启动进程、失效 PID、端口被当前服务或其他进程占用、异常退出和日志路径。
- 验证运行时、包管理器、依赖、环境变量、配置格式、目录权限、端口和外部必需服务自检。
- 验证数据库驱动、服务、Socket 或 TCP、认证、目标库、权限和 Schema 版本；数据库不可用时服务不能伪装正常。
- 验证自动修复只处理已声明的无破坏事项，记录原因、动作、结果并复查；阻断项以非零状态退出。
- 验证 `localhost`、本地域名和当前 IP 的实际可达性，以及绑定地址、允许主机、CORS 和 WebSocket 配置。
- 检查成功输出中的 PID、地址、数据库状态、自检摘要、修复和日志均真实；不可用 URL 被单独标记。

## API 与文档验证

- 如果本次新增、修改或明确审查 API 或接口文档，检查接口卡片、请求、响应、错误、权限安全、数据口径或副作用、调用入口和验证状态完整。
- 仅在上述 API 范围内校验示例字段、类型、枚举、默认值、分页、批量和错误码与实际实现一致，且不含敏感信息。
- 检查本地 API 与外部接口分开维护，README 只提供入口和摘要。
- 检查目标项目依赖文档与跨项目知识库职责分离：前者记录当前项目实际调用和落地，后者只在确有复用交付时使用独立索引、稳定元数据和一条目一文件结构。
- 如果本次创建、修改、迁移或明确审查知识库，检查索引覆盖全部条目，稳定 ID、Method 与 Path 无重复，状态和验证记录一致；旧汇总、临时导入文件、本地地址、未脱敏内部地址和认证值均已清理。
- 检查规范包安装或升级没有创建、覆盖或删除目标 README、`knowledge/` 和真实 `.env`。
- 如果本次按明确条件创建、修改或审查 README，检查项目定位、状态、使用或启动方式、主要入口、环境要求和文档导航均来自当前仓库证据，不包含模板内部场景说明。
- 仅在上述 README 范围内检查 TODO、TBD、待补充、项目名称等占位，以及旧命令、旧路径和失效入口；待确认内容应明确说明未验证原因。
- 检查功能基线、架构、数据模型、配置、任务、指标、运维和安全文档与当前代码和页面一致。
- 检查当前事实与计划项分离，未实现能力没有写入当前主路径文档。
- 检查 Markdown 结构、表格、Mermaid、链接、文件路径、页面入口、接口路径、表名和配置项。

## 交付说明最低内容

- 本次完成的主路径调整和已删除的旧口径。
- 实际执行的测试、构建、浏览器、数据或运行验证及结果。
- 没有执行或未通过的验证、原因和剩余风险。
- 涉及数据迁移、临时措施、外部契约或后续下线项时，写明影响范围、责任和后续动作。
