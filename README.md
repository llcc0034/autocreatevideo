# Media Asset Production

面向单人或早期团队的媒体资产与内容生产平台。系统把剧本、人物/场景/道具（Bible）、镜头、生成调用、受管产物、逐集母版和发布包串成可审核、可追溯的生产链路。

## 当前能力与边界

- 短剧生产从项目工作台创建 `ProductionRun`，明确选择配方制作或无配方人工制作。人工方式不要求隐藏配方，也不会创建后自动调用模型。
- 每次生成选择精确的执行实例版本，复用部署、工作流、提示词策略及原任务队列；输入、参数、来源与审核依据由执行准备冻结。
- 生成、审核、采用、装配和封存是不同动作。模型成功不等于内容已采用，逐集母版也不等于已封存为 `ReleaseBundle`。
- 素材库可独立上传或按执行实例生成素材；它不创建或推进短剧运行。“任务中心”用于任务查看与各自允许的恢复操作，不是第二个短剧创建入口。
- 预算、调用次数与平台文本输出额度由系统配置统一管理；超额进入人工确认，已提交请求不被动态配置改写。外发授权、真实模型能力、权限、安全和未知结果核对仍独立保留。
- ComfyUI工作流支持分阶段纳管、语义接线与版本化Projector；Validate、资源Smoke、执行实例组合Smoke和发布是不同事实，不能互相替代。
- 权限与受管凭据沿平台统一入口管理；敏感值加密保存，普通页面/API不返回凭据材料。

以上是实现边界，不是全部生产验收已通过。部分图片、人工视频与装配有历史实测；后续配置重建不继承旧验收证据。任务中心与输入/提示词/输出历史已接入；当前仍有人工步骤状态与结果恢复入口、烟测具体诊断、模型通用参数表单和来源/输出配置缺口，见[优化与待办](docs/optimization/README.md)。完整配方生产、未覆盖媒体协议、最终效果/封存及恢复验收见[当前工作包](docs/optimization/records/execution-unification/2026-09-25.md#current-work-packages)。

平台不会自动下载模型、守护新的文本推理运行时或把worker并发当作多GPU调度器。异步REST参考媒体须有已支持的上传合同；缺失时不伪装可用。测试与历史小样片不替代目标环境真实验收。

## 技术与事实来源

后端为Django + Django REST Framework，前端为Vue 3 + TypeScript。PostgreSQL（开发默认SQLite）保存业务事实、队列与审计；媒体进入受管存储。Schema唯一入口为[模型](backend/studio/models.py)与[Django迁移](backend/studio/migrations)，机器API唯一契约为[openapi.yaml](openapi.yaml)。

## 首次安装与日常启动

Windows PowerShell：

```powershell
.\scripts\setup.ps1
.\scripts\restart.ps1
```

首次安装流程、环境依赖、受管凭据与账号初始化见[运行手册](docs/operations.md)。新机器从干净源码和空库运行 `scripts/setup.ps1 -Fresh`，默认不带演示项目或导入素材；现有安装的历史清理及独立素材批量删除也见运行手册。日常启动/重启只使用 `scripts/restart.ps1`；仓库没有独立的本地停止脚本。不要为旧验收记录重跑维护清理或另建服务管理入口。

## 开发与使用入口

- 前端：`http://127.0.0.1:5173/`
- 后端存活检查：`http://127.0.0.1:8000/api/v1/health/`
- 动态Schema：`GET /api/schema/`，与根OpenAPI同源
- 项目工作台：连续剧创建、制作、审核与交付
- 风格素材库：素材上传、生成与管理
- 系统设置：模型/工作流/执行实例/策略/系统配置
- 页面内“操作手册”：生产步骤与系统设置指南

## 检查与投产

统一工程检查入口：

```powershell
.\scripts\check.ps1
```

工程检查通过不等于真实模型或GPU生产通过。投产须另按[生产就绪检查](docs/production-readiness.md)核对当前精确版本、实际输出、逐集交付与完整备份恢复。
