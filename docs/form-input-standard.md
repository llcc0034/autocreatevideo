# 填写表单最小输入标准

本标准适用于平台所有新增、编辑和创建后继版本的业务表单。目标是让操作员只确认真正具有业务含义、且服务端无法可靠推导的事实；技术字段、目录字段和版本字段不得继续伪装成普通文本框。

这是表单设计标准，不是所有页面已经达标的声明。2026-09-21审核确认模型媒体规格仍有高级JSON独占编辑缺口，实施范围统一登记于[OPT-MODEL-FORM-001](optimization/registrations/opt-model-form-001.md#opt-model-form-001-模型通用参数表单化与统一参数目录)。

## 字段所有权

| 类型 | 页面行为 | 提交行为 |
| --- | --- | --- |
| 服务端目录 | 使用下拉、单选或多选；选项来自同一领域的 `options` API | 只提交选项稳定值；目录缺失、重复、过期或含未知值时失败关闭 |
| 系统维护 | 显示为只读结果或完全隐藏，例如版本号、结构版本、排序和新建生命周期状态 | 普通表单不提交；服务端忽略或拒绝客户端伪造值，并在事务内分配 |
| 业务事实 | 保留必要的文本、数字或结构化控件，例如显示名称、含义、影响和真正的新稳定标识 | 按类型提交并由服务端再次校验 |
| 开放标准或新目录值 | 只有服务端在 `custom_entry_fields` 明确授权时显示“高级登记”入口 | 必须显式进入高级入口并满足稳定格式；不得在目录读取失败时自动退化为自由文本 |
| 已冻结结构 | 已有 revision、published 或 retired 后显示为只读 | 结构变更必须创建新 key 或后继草稿；普通编辑只发真实差异字段 |

## 通用规则

1. 页面不能从多个候选中默认选第一项。只有服务端证明候选恰好唯一时，才可自动填入该唯一合法值。
2. 新版本号、合同 schema 版本、展示排序和创建时生命周期状态由服务端维护。配方与提示词策略的已有版本只能从精确来源及 SHA-256 创建后继草稿。
3. `options` API 是表单目录的唯一事实源。读取开始先清空旧目录；网络失败、响应字段缺失、空值、重复值或授权元数据缺失时，按钮、打开、校验和提交四层都必须阻断。
4. 折叠和隐藏只用于降低阅读负担，不能制造第二份可写事实。普通表单不得用完整 JSON 覆盖已经拆出的系统字段或受控目录。
5. 编辑只发送相对打开表单时原始快照的差异 PATCH。服务端仍按真实值变化判断不可变字段，不能因客户端重复携带相同结构值而误判冲突。
6. 所有目录值、系统默认、可写字段集合和版本冲突必须进入 OpenAPI、正式测试和页面提示；前端本地常量不能成为第二事实源。
7. 通用参数名称、类型和单位由平台合同声明；有限枚举使用选项，合法连续数值使用带约束的数字框，不能把可变范围随意固化为几个值。自定义业务名称和说明仍允许必要的文本输入。
8. 模型约束Key、运行参数语义Key与Projector节点映射职责不同；共用受控目录并展示实际来源，不要求用户手抄Key，不依据同名字符串推断关联。模型通用合同完整表单化后，完整JSON只作核对，不再保留可绕过表单的第二写入口。

## 当前管理表单合同

- ProductionRecipe：`GET /api/v1/production-recipes/options/` 提供阶段、执行方式、审核门禁、路由策略、预设和结构版本；`clone-successor` 由服务端校验精确摘要并分配下一版本。
- PromptProfile：`GET /api/v1/prompt-profile-versions/options/` 提供模型族、operation、mode、投影器、字段规则目录、系统默认和高级登记授权；新建固定为 `needs_review`。
- 系统设置 → 字段维护是字段身份及定义版本的唯一管理入口；Profile只选用版本并提供跳转。字段身份：`GET /api/v1/field-definitions/options/`只提供身份系统默认；展示排序由服务端追加，新建固定启用。定义内容通过`field-definition-versions`维护，类型/状态从其options读取，版本号由服务端分配；规则引用确切可用定义版本，不自动改选。
- ConfigDefinition：`GET /api/v1/config-definitions/options/` 提供配置类别、值类型、作用域、默认来源、域、单位、影响模块、系统默认和高级登记授权；响应中的 `has_values` 与 `mutable_fields` 决定已有 revision 后的只读范围。

新增其他填写表单时，应复用共享目录选择组件和同一失败关闭校验链；若某字段无法归入上述所有权类型，应先补充服务端合同，而不是先增加自由文本框。
