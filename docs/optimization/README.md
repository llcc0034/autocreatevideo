## 后续如何维护

- **需求状态与启动条件**只写新待优化清单；设计与勾选只写对应模块设计；当前工作只写current.md，索引不再复制状态段。
- **任务与记录分开**：前端正式任务固定为UI-H01～UI-H12，主清单每项只保留职责、简短状态／缺口和语义证据链接。历史`18.14.xx`是定位编号，不能加为子复选项或计入任务数量；旧锚点保留，新增证据用“模块／日期／语义标题＋关联任务ID”，不续增旧章节流水号。
- **证据**追加到records/功能模块/YYYY-MM-DD.md；同日同模块合并，跨模块单存一份并在索引关联，不到多个文档复述。
- **每轮记录**仅新增完成、剩余缺口、具体阻塞及必要证据链接；已过且未受影响验证直接引用。长日志／截图继续放.artifacts，不粘贴正文。
- **额外优化**去重后登记到新清单并关联原模块，不顺带扩项；完成项移为证据链接，不重开已交付模块。历史中的旧“下一步”、权限或环境状态不覆盖新指令。
- **验收**保留原标准；纯文档调整检查归属、内容保真、链接及续接路径，不重跑无关前后端测试。
