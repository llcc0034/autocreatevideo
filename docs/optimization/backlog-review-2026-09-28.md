### A01 平台字段中心、输入输出合同与映射

**来源**：`OPT-IO-CONTRACT-001`、`OPT-PROMPT-SOURCE-001`、`OPT-MODEL-FORM-001`、`OPT-CONFIG-GENERIC-001`的字段/常量收敛部分，第143批V0-F；输入缺失治理作为需单独确认的子范围。

**已有**：M1-01至10已完成独立“字段维护”、定义/结构/映射版本基础和配方/实例/策略消费者接入及开发验收，通用结构化文本G01至06已完成；现用页面与隔离消费者证据及未执行范围见详细设计5.4。用户手动试用异步，接续M2-01。后续剧本、Bible、分镜等业务writer仍按M2–M8改造，不能把基础能力与既有第89批证据当作全链完成。具体勾选和验证仅在详细设计维护。

**范围与后续业务接入**（下列是A01总范围，已完成基础不重复立项；剩余项以详细设计为准）：

1. 系统设置增加“字段维护”大类：字段定义、输入/输出结构、来源与映射、样例预览和引用影响。稳定身份、显示名/含义、类型、嵌套、集合、单位/枚举、约束、生命周期和精确版本同源管理；不用一个文本说明代替结构合同。
2. 各步骤的输入表单、模型输出要求、解析校验、审核展示和下游可选字段共用合同。覆盖剧本生成/结构化、Bible/设定、图片生成、提示词辅助/组装、媒体生成、审核、装配与交付的业务输入输出，不只改剧本或菜单。
3. JSON字段改名、层级、集合通过受控映射处理；未知自由文本沿原AI结构化与人工核对链转成所选合同的候选，保留原文。分隔符是可选格式策略，不承诺无配置准确解析一切未知文本。
4. 自定义创作字段不丢失，可直接用于下游提示词。要驱动实体、变体、分镜、时间等业务动作，必须显式映射到该能力的语义输入，不能靠字段名或说明猜测。新增支持类型的业务字段不再改代码；全新执行器、解析算法或业务动作仍需开发。
5. 字段定义不含任务实际值；输入/输出方向和步骤必填规则属于使用关系。配方负责上游到逻辑输入，实例负责逻辑输入到执行目标及结果映射；字段中心提供共用编辑/影响入口，不另存第二份接线。媒体保留确切受管素材/产物版本及manifest引用，不塞Base64或临时URL。
6. 版本随本次准备/请求固定，保存/使用前给出样例解析和映射错误；不增加多层人工发布审批。清理被替代的固定业务字段、别名、重复字典和双路径；不适配的开发数据可清理，不为旧合同保留解析器。
7. 媒体字段的来源方式可配置为本次上游输出、Bible主图/指定变体、素材库选取或本地上传后入库；每字段声明允许来源、默认方式、是否允许本次改选、数量/用途/顺序。显式选择哪一种就使用哪一种，不隐式混合或回退。该装配能力用于整个平台，不是某配方的临时覆盖开关。

**缺失处理范围**：M1必须支持字段使用处的必填/可选、null/空值与0/false区别、显式默认值及基础嵌套类型检查，这是字段功能的一部分；已有局部 `if_missing` 不能算全链完成。原[缺失治理方案](records/execution-unification/2026-09-26.md#input-missing-policy-plan)中的高级缺省转换、批量影响治理或额外发布门禁不自动纳入，保留另行确认，不将基本字段功能与整包治理捆绑。

**完成条件**：至少用不同JSON布局的剧本、一个非剧本自定义字段，以及文本/嵌套集合/媒体引用，验证“配置→输入/输出→审核→下游”无新增字段专用代码；覆盖所有生产步骤及权限、错误路径、版本漂移。有限基础类型、权限、完整性和执行协议仍由代码保证，不开放任意脚本/数据库路径。

**字典归并口径**：升级现有PromptProfile“通用字段字典”为平台字段维护，保留有效字段身份，不建设第二个字典。字段定义、结构使用关系和提示词装配职责分开；全局必填/实际默认迁至使用处，预览样例不进实际值。具体版本/接口/首版格式边界见已批准详细设计M1及R01/R02，当前基础实现和未验范围按唯一清单接续，不再等待重复审核。

### A02 剧本声明、Bible主图/变体与逐镜精确素材引用

**来源**：`OPT-REFERENCE-VARIANT-001`的V0/V1/V2/V3；通用字段机制归A01，不重复建设。

**已有**：生成/结构化请求已接声明合同；主图/变体设定修订、来源物化和原Bible人工审核已有隔离验证。V0-e2c只读分镜关系预检有19项组合测试证据，**生产writer尚未切换**。0197/0198迁移有开发记录但未获现用库应用证据；V1页面基础不能视为完整变体生产。

**剩余目标**：

- 按A01合同调整剧本生成与结构化规则，明确实体、共同身份、主图设定、变体造型/状态及逐镜场景、可见对象、对白参与者、素材用途。来源事实与允许的设计补充分开；对白发言者不等于全部出场对象。
- 按A01新合同适配并回归已有Bible来源/设定幂等物化；新增类型化分镜关系并切换唯一writer，不把e2a/e2b已完成的物化重做一遍。不从自然语言/译名反推关系，不补造旧剧本声明。关系预检共用字段/映射机制；身份、跨项目、引用完整性等校验不能配置成绕过。
- **模型生成变体时，先取得并选定主图，实际输入该图片版本与变体差异设定**；选定可以由配方明确的自动规则完成，也可以人工选择，不强制增加人审。不能分别文生图或拿描述冒充图片，兄弟变体不自动串联。直接上传/选择已有变体只建立关联，不强制重生成或伪称曾参考主图生成。
- 主图更换需展示对未执行项的影响；已生成变体和历史请求保持原主图依赖，不自动改绑/重生成。重新生成必须是明确的新操作和新版本。
- 实例明确支持图片输入及对应用途；配方可配置主图到变体的依赖/来源/审核，缺图或不支持即明确等待/报错，不隐藏回退。核对现有通用能力，不以图片输出推断支持图生图。
- 镜头引用稳定实体、变体修订、确切选定素材与用途；同一个Bible可有不同服装、视角、图片/视频/音频，候选版本与变体不是一回事。按配置规则自动传递；无法按规则唯一确定时提示选择，不按译名或未配置的“最新”规则猜图。
- 素材库管理作为M9独立模块，支持主图、变体和版本关系的浏览/上传/选取；主图与变体的模型生成按钮调用M4共用能力。素材可独立于Bible存在，关联后也不复制文件或另存第二份素材。
- 全自动短剧从结构化剧本提取本轮未知实体与素材需求，自动执行主图→变体→入库→镜头引用；不要求先手工建库。素材库独立操作只是另一种入口，不替代配方链，也不强制创建剧本或ProductionRun。

**完成条件**：分别验证从新剧本自动发现需求并生成素材，以及无剧本的素材库独立上传/生成；同一实体主图和至少两个变体，实际生成请求携带正确主图，上传/复用路径不发多余模型调用，结果在素材库及关联Bible一致展示，镜头引用确切文件。自动流程无需逐项人审，人工策略仍有操作入口。各模块先独立验收再做组合，不包含D06的所有权/附着语义。

### A03 素材名称绑定与动态视频提示词

**来源**：`OPT-REFERENCE-VARIANT-001`的V4；引用名绑定从原名称问题中分离，语言润色仅留O03。

**已有**：完整提示词预览、已冻结实际请求只读展示及超限全文/分项计数已有第140/142批证据，不重建。当前名称/外观投影仍须按新要求整体收敛。

**剩余目标**：

- 引用名称可用任意语言，名称不是实体ID或图片编号；以稳定实体/逐次使用标识及确切素材身份建立映射，一次请求集中展示“名称、素材/版本/用途、真实槽位标记”。名称仅是受保护展示值；同名、多语言及Unicode等价冲突须消歧，禁止跨实体按名字全局替换。
- 视频辅助任务和最终装配只取得必要素材名称、引用关系及动态事实，**不再系统注入Bible外观锚点、参考图生成提示词、prompt_hint或重复保留分析**。不只删最终模板，却让辅助模型收到静态锚点后再写回。
- 正文聚焦动作、交互、构图/机位/运镜、时间、对白和声音；保留原作者对白，不由翻译改写。图片生成仍需要设定/外观信息，与视频提示词职责分开。
- 通用、版本化投影/装配配置控制上述边界，不硬编码人物、语言、模型或某配方；真实输入槽位和受保护引用保持一致。

**完成条件**：不同语言名称、多变体、多媒体引用均对应正确输入，输入顺序变化后按实际槽位重新编号；辅助请求及最终提示词没有系统重复注入静态锚点，不靠对已有人工作品/自由文本关键词删句伪装净化；全文、长度、采用修订、真实参考顺序均可核对。字段与通道的长度配置同源于A01约束及本组装配策略，不默认提高限制。超限显示全文不等于允许提交；质量提醒不覆盖接口硬限制。

**容量核对（2026-09-28用户确认并入验收）**：精简后顺带记录最终提示词长度及完整准备记录的实际序列化字节数，包含输入、来源证明、参数/合同和辅助字段请求，核对各自生效上限；不能只凭正文变短认定整份准备已不过限。使用代表性隔离样例核对原准备写入/读取是否正常，不另建存储重构或性能认证项目，不截断正文/审计证据或自动提高上限来制造通过。若仍有实际超限或读写异常，记录分项数据与复现证据，另提方案并取得用户确认；不自动恢复D01，也不将尚未完成的检查记为存储问题已解决。

```text
全自动短剧：
剧本生成/结构化 → 本次实体、主图/变体设定及镜头素材需求
  → 配方调用共用生成能力：主图 → 以主图为图片输入生成变体
  → 结果自动入素材库并建立关联 → 分镜装配 → 提示词 → 视频 → 交付

素材库独立操作：
上传/选取/模型生成主图 → 上传/选取/参考主图生成变体 → 同一素材库

字段装配：按配置取本次上游结果 / 指定Bible主图或变体 / 已有素材 / 上传后入库素材
```

- 自动链的内容在运行中从剧本产生，不能要求先手工建Bible、素材库或逐张选择。流程明确选择自动模式时，技术输入可用即可按配置接续；人审模式保留既有正文/单镜/批量入口。
- 独立素材库无需剧本或配方；图片、视频、音频和其他已支持素材可独立管理。主图/变体关系并非所有素材的强制属性，未绑定Bible的素材也能直接作为模型输入。
- 主图或变体均可上传、选已有图片或调用模型。**生成变体必须真实输入主图；上传/复用已有变体不触发模型，也不能记录成“模型参考主图生成”。** 参考基准明确关联，但不把已上传图强制重生成。
- 素材文件及身份只有一份，Bible和镜头保存关联。候选版本与造型变体分开；名称可用任何语言，实际输入按素材身份、用途及顺序绑定，不按名称匹配文件。
- 每个输入字段可配置允许来源、默认来源和是否允许本次改选。默认自动读取上游与显式选择已有素材都是正式方式；改选只影响本次输入，不自动改Bible默认主图。已有素材可满足相应生成目标时，配方应支持显式复用而跳过该目标的多余生成；其余未满足目标继续按剧本生成。
- 仅要求所选模型真实支持相应媒体类型、数量和用途；不支持时展示原因，不丢掉参考图降级为纯文本。底层全新执行器/未知解析算法仍需开发，不宣称字段配置能生成任意新算法。

### 8.3 实施顺序与模块交付方式

1. **M1先行**：先完成最小可用字段定义、结构/解析映射、媒体来源选项和配置预览。用两个布局样例交用户试用，不等待全部消费者接完才交付；后续模块逐个替换固定字段，全链未接完不宣称“全平台已去硬编码”。
2. **M2→M3；M9基础管理可独立推进**：剧本和设定沿业务顺序；素材库先完成上传/选择、主图/变体关联与展示，凭已有图片独立验收，不依赖剧本生成。M9此时只完成基础部分，不能报整个模块完成。
3. **M4＋M9生成入口联调**：在稳定素材关系上实现共用生成；同时验素材库独立生成和配方按剧本需求自动生成。变体必须实际输入主图，自动模式不强制人审。M4通过后补齐M9模型按钮验收，消除“互相等待整包完成”的循环依赖。
4. **M5→M6**：先验证分镜精确素材绑定，再验证引用名和动态提示词；可先用已有素材，无需为调试反复跑图片模型。M6顺带核对准备记录容量，不另开D01。
5. **M7→M8**：媒体执行/失败恢复和选片/交付分别验收；已有队列、恢复、装配能力只补缺口。与上游无依赖的既有失败恢复可提前修，不能形成第二执行链。
6. **新链组合复验**：使用新剧本、新配方、新Run验证自动需求→主图→变体→引用→提示词→视频→交付；另验显式复用已有素材的混合来源场景。不是重新开发一个全平台总包，不复用旧Run续跑或历史成功来充数。

详细设计批准后，每模块按“已批准细任务→页面/API/逻辑实现→匹配开发验收及修复→交付手动试用入口”推进；每完成一项即时在[详细设计](module-development-detailed-design-2026-09-28.md)勾选并附证据。按2026-09-29最新指令，用户手动验收异步反馈，不阻塞依赖满足的已批准工作，不反复要求继续。新增需求/改变合同或验收边界仍须确认；未做真实模型验收不以夹具冒充。
