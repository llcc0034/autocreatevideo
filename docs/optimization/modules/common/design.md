<a id="12-不扩散需求的执行约束"></a>

### 1.2 不扩散需求的执行约束

1. 每次开发只能选择本文**已批准且依赖满足**的任务ID，先声明该工作段包含哪些ID和不包含什么。
2. 细任务中的“实现、产出、验收”共同限定范围；不能以“通用化”“顺便治理”“后续可能用到”为由追加功能。
3. 新业务字段类型、新解析算法、新执行协议、新页面功能、新业务动作、额外审批/认证、扩大数据清理范围，均先提出变更，等待用户确认后修改本文、再开发。
4. 变更申请至少包含：原任务ID、具体问题/证据、建议增删内容、影响模块/数据/API、新增验收条件、依赖/工作量变化、用户决定。未确认的建议记在第18节，不进入任务清单。
5. 为满足既定验收而修复缺陷、调整内部函数/文件组织、补同范围测试，不视为新增需求；若改变已批准的业务语义、接口合同或验收标准，仍需确认。不得降低验收条件来勾选完成。
6. 已批准的普通技术小步骤连续推进，不反复等用户说“继续”。2026-09-29用户进一步明确：不偏离计划方向的测试验收及问题修复直接执行；开发验收完成后提供手动试用入口，用户的手动验收异步反馈、不阻塞后续开发。2026-10-02进一步授权：各模块完成除环境切换外的事项，即按M1方式自动切换并报告手动试用入口，不等逐次切换指令，具体操作边界见更新R06。仅新增需求、方向变化或超出已授权操作范围时再确认。
7. 不做历史兼容。每个模块同步清理其替代的旧代码、旧配置定义、别名、页面、路由、测试及失效说明；不能把“保留旧逻辑以防万一”作为默认交付。

<a id="13-状态打勾与证据"></a>

### 1.3 状态、打勾与证据

- 初始所有任务均为`[ ]`。现有源码或历史测试只是复用基础，不能直接给新任务打勾。
- 任务状态：未开始、进行中、已实现待验证、完成、阻塞；状态可写在对应任务下，不另建重复任务表。
- 只有任务的产出和列明的开发验收全部满足，才将对应`[ ]`改为`[x]`，**完成一项就即时更新，不等整模块结束**。同时附日期、改动入口、验证命令/结果或证据位置、未验证范围。
- 代码检查/隔离测试、现用页面验收与用户手动试用分别记录。各模块最后一项在约定开发验收和交接满足后勾选；按2026-09-29最新指令，不再以用户未反馈作为阻塞或保持未勾选的理由。仍须明确尚未验证的真实目标，不把手动未验写成手动通过，不降低任务本身的验收条件。
- 不把不同源码快照下的测试数相加成一次完整回归；不以文档检查、模拟响应或任务已排期证明真实模型可用。
- 勾选示例：`[x] M1-02 …；完成：日期；证据：文件/测试结果；边界：隔离库，未迁现用库`。本稿没有使用该示例冒充任何实际完成项。

## 2. 需求基线与不做事项

<a id="21-要解决的业务问题"></a>

### 2.1 要解决的业务问题

1. 剧本及下游字段当前部分固定在代码中，改字段名/嵌套就容易触发新的解析开发；旧提示词字典与输入输出定义职责不清。
2. 剧本虽已有Bible描述，但主图、变体设定、逐镜用哪张图未形成完整、明确的通用链；无法仅靠英文名称或自由文本匹配保证正确素材。
3. 独立素材库与自动生产都需要主图/变体管理；既不能要求全自动短剧先手工备库，也不能要求独立素材生成先建剧本。
4. 变体不能只根据相似文字独立生成；必须真正以指定主图为输入，改变服装/状态等设定，同时保留来源关系。
5. 视频提示词重复注入静态外观锚点、名称不稳定，增加长度又影响参考图对应；应转向素材引用名和动作/运镜等动态内容。
6. 准备、辅助生成、主调用、候选与采用状态混淆；失败不显示实际内容、恢复误跑成功项、逐字段确认成本高。已有改进应复用并接入新合同。

### 3.1 配置与事实的职责

| 层 | 保存什么 | 不保存/不决定什么 | 权威维护入口 |

现有“通用字段字典”并入字段维护：保留有效字段ID和引用，`PromptFieldDefinition`用Django模型/表重命名方式收敛为平台字段对象；新增不可变定义版本。所有调用方一次按新合同切换，不留旧字段API别名。名称相同但语义不同的不自动合并；提示词专用字段可作为分类保留。当前全局必填/默认值按明确使用场景迁至结构/来源；无法明确归属的旧开发配置清理，不推断或双读兜底。

<a id="32-最小字段与结构合同"></a>

### 3.2 最小字段与结构合同

以下是**已获用户批准的首版设计**，不是已发布Schema或功能已实现声明。

- 字段基础类型：短/长文本、整数/小数、布尔、枚举、对象、列表、媒体引用。对象子字段和列表元素定义在结构中；媒体类型/数量/用途在使用处配置。日期等首版按有说明的文本处理，不另加日期表达式系统。
- 稳定字段ID不依赖显示名或外部JSON属性名。外部`people`、`cast`均可配置映射到同一人物集合语义，但不要求两份剧本采用同一个拼写。
- 结构节点包含：节点key、引用字段版本、对象属性名/列表元素、顺序、必填、是否允许null、是否允许空字符串/空集合、适用范围/枚举/长度等。根对象及每层嵌套均显式描述。
- 缺失规则只支持：报缺失、省略可选节点、采用显式配置默认值。默认值仅在键不存在时使用；null是否允许单独判断，空字符串/空集合也单独判断。`0`与`false`不是缺失。默认值来源必须可见，不覆盖已存在的值。
- 新增自定义字段须登记并加入结构后才能被表单及下游正式使用；结构外字段在原始返回中保留并提示“未映射”，不悄悄丢原文，也不自动晋升为平台定义。
- 字段/结构采用草稿→可用版本→停用的简单生命周期；保存草稿可不完整，使用前检查类型/引用/映射一致性。没有额外人工发布审批；已被请求使用的定义通过新版本修改。
- 任务保存所用结构、字段及映射版本；后续配置修改只作用于新准备。显示名可更新的管理行为不能重新解释已经冻结的任务值。

**目标数据对象**：升级现有字段定义并增加`FieldDefinitionVersion`；增加统一`DataStructureVersion`（名称为设计名），输入和输出都引用它。`ContentSourceVersion`继续负责读者合同，`BusinessOutputVersion`继续负责结果解析配置，两者引用结构，不各自复制一套字段Schema。结构/映射是定义数据，业务ID、状态、关系等查询事实仍使用明确模型字段/关系；不把整个平台改成无约束JSON大表。

<a id="33-格式解析与业务语义"></a>

### 3.3 格式、解析与业务语义

已批准首版：**确定性结构化格式采用JSON；自由文本、分隔符剧本等沿现有AI结构化入口转换为所选JSON合同，再供同一解析器消费。** 配置可改变字段名、层级、集合及映射，不为每份剧本重写代码。不新建“任意自定义文本语法DSL”；如后续要求特定分隔符文本也必须无AI确定性解析，另行确认格式及验收样本，不能开发中自行加解析器。

确定性映射只提供本轮需要的能力：对象属性路径、显式列表逐项映射、嵌套对象构造、固定值、按稳定声明key查找已解析实体/设定关系。路径从合同目录选取；不执行自由表达式/脚本，不做隐式字符串转布尔/时间单位猜测。单位转换若实际需要，先确认具体转换规则，而非引入转换语言。

解析流水：原始内容→按所选合同解析/基础校验→结构化值和路径错误→可读表单/审核→明确来源映射→下游逻辑输入→既有业务动作。解析只负责结构；创建Bible/镜头等动作由各模块唯一服务执行，不能通过任意字段定义直接触发数据库写入。

平台需保留**有限、明确的业务能力输入目录**，例如实体身份、设定关系、镜头坐标、可见主体、说话人、素材用途。字段映射到目录后才能驱动这些动作；新增自定义创作文本可直接进入提示词，但不会凭说明自动获得新的业务行为。“配置化”不等于消灭全部领域代码。

样例：布局A使用`episodes[].shots[].action`，布局B使用`chapters[].frames[].motion`；两者映射到同一镜头动作字段。另加任意命名的`mood_note`文本并映射到视频辅助输入，不改解析器/页面组件即可显示并消费。样例不成为产品固定字段。

<a id="34-素材设定与版本关系"></a>

### 3.4 素材、设定与版本关系

| 概念 | 含义与单一事实来源 |
| --- | --- |
| Bible实体 | 剧本中的稳定人物/场景/道具，不等于图片文件 |
| 主图/变体设定 | 共同身份、主图外观、特定造型/状态差异；复用`BibleVariant`及修订。一个“校服”设定可有多个生成候选，不按候选次数创建新变体 |
| 素材系列（目标新增关系） | 同一主图或某个变体的候选/版本集合，可独立存在；变体系列指向主图系列，可选关联一个Bible设定。只管理素材关系，不复制Bible锚点正文 |
| 素材版本（目标新增关系） | 系列内有序记录，指向确切`Asset`及来源生成/上传记录；新候选另建记录，不覆盖文件。首版不建设全平台通用文件版本引擎 |
| 生成依据 | 模型生成变体记录确切主图素材版本、设定修订和请求；上传/复用仅记录关联来源，`generated_from`为空，不伪装参考生成 |
| 逐次素材使用 | 某镜头某用途使用哪个素材版本及可读名称，由M5保存；M6按本次输入顺序转成真实模型槽位 |

素材系列可用`AssetReferenceSeries`（设计名：名称、主/变体角色、父主系列、可选Bible设定引用），版本关系可用`AssetReferenceVersion`（系列、序号、Asset、生成/上传来源、实际依据版本）。`Asset`仍是唯一文件及媒体事实；不复制文件/字节，不把媒体关系塞入无索引metadata代替明确关系。独立图片/视频/音频不要求强行组成主/变体系列。

Bible设定名与素材引用名职责不同：前者标识创作设定，后者标识本次用到的具体素材。可用“沈念·校服正面”“沈念·外套侧面”等任意语言名称；它们是示例，不是内置命名规则。自动名称从所选设定/系列的配置规则生成，冲突通过可见的用途/版本短标识消歧，不用翻译推断身份。

主图设定更新与主图素材更换是两种操作。已有请求/已生成变体继续指向旧依据；未执行项展示依赖变化并按本次明确选择重新准备，不能悄悄改绑。首版只支持变体参考指定主图，不展开兄弟变体串联/任意多级变体树。

<a id="35-媒体来源和自动人工策略"></a>

### 3.5 媒体来源和自动/人工策略

每个媒体输入用同一来源控件和解析服务，配置`允许来源、默认来源、本次是否可改选、媒体类型、数量、用途、顺序`。来源包括上游所选产物、指定Bible主图/变体、已有素材库Asset、本地上传后形成Asset；文本字段另支持显式固定值/上游字段。选择某来源后只读该来源，不失败后偷偷换另一张图。

生成目标还需区分“生成新素材”和“直接使用已有素材”：已有素材满足目标时该单元标明复用并不发模型任务；将现有图作为生成参考则仍会发任务，两种操作不能同名。

首版自动策略采用可解释的确定规则：每目标可配置候选数；自动选择按本次候选序号选首个满足基础文件/结构要求的成功项，不按模型主观评分；人工策略由用户选定。按该规则已产生的选择不因迟到候选静默改选。没有候选可用就报告失败；存在无规则可解释的歧义则待选择。自动模式不伪造人审记录，人工模式不被代理代选。这是已批准默认设计，不增加质量排名系统。

<a id="36-错误质量与界面"></a>

### 3.6 错误、质量与界面

- 类型/必要输入缺失、引用不存在、文件不可读、目标不支持参考输入、外部接口真实上限：解释具体路径及解决操作，限制错误请求提交。
- 文风、建议字数、细节充足度等质量问题：保存并展示实际输出，给出提醒/建议；人工模式可编辑或采用，自动模式按已选策略继续，不暗中切换成逐字段人审。
- 模型返回可读但不合结构时保留原文，提供编辑/再次结构化入口；解析失败不能冒充字段已保存，禁止用空正文盖住实际返回。
- 准备状态、辅助调用状态、主调用状态、字段确认/采用状态分列；“辅助成功”不等于“视频成功”。已取消终态不再提示等待后自动继续。
- 页面正文/预览优先，UUID、完整合同和原始JSON折叠；错误保留具体单元/字段位置。新控件沿用现有操作台组件，不启动全站美化项目。

<a id="39-字段可配置性的验收示例"></a>

### 3.9 字段可配置性的验收示例

以下仅为隔离样例，不是平台内置协议，名称和值均可替换：

```json
{
  "布局A": {"episodes": [{"shots": [{"action": "转身看向门口", "mood_note": "紧张", "voiceover": false}]}]},
  "布局B": {"chapters": [{"frames": [{"motion": "转身看向门口", "tone": "紧张", "off_screen": false}]}]}
}
```

实际测试将A/B作为两份独立输入，分别配置结构和路径：`action/motion`引用同一个动作字段身份，`mood_note/tone`引用新增的自定义文本字段身份，`voiceover/off_screen`引用同一个布尔字段身份。M1解析后M2表单能显示它们，M6通过所选Profile消费动作和自定义文本；false不会被默认值替换。新增自定义字段时只操作配置页面，不修改Python/TypeScript源文件。

实体/变体示例则使用结构中的稳定声明key关联：镜头引用`实体key + 设定key + 用途`，M5再绑定`素材版本`。生成的文字名称只负责可读性，不用上述JSON属性名、翻译或文件名替代引用身份。
