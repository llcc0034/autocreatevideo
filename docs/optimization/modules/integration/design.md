## 15. 验证设计与INT新链组合验收

<a id="151-验证分层"></a>

### 15.1 验证分层

| 层 | 做什么 | 不能据此宣称什么 |
| --- | --- | --- |
| V-doc 文档设计 | 链接、任务ID、依赖、需求归属、状态和边界检查 | 不等于功能已实现 |
| V-code 模块开发 | 关联单元/API/组件测试、类型/构建、Django检查、适用隔离迁移及旧路径搜索 | 不等于现用服务已加载或真实模型成功 |
| V-ui 模块试用 | 页面样例操作、错误/等待/取消/部分失败、实际请求字段核对 | 不等于远端模型具备未测能力 |
| V-real 真实目标 | 获准后使用所选实例，核对实际传输、可读取/播放产物和来源 | 不替代艺术质量评价或目标环境PG/性能验证 |

每模块只运行与改动匹配的验证；稳定组合后执行必要整合检查，不在每次汇报重复全套回归。后端使用项目既有`manage.py test/check/makemigrations --check --dry-run`；前端既有Node测试、类型和构建；整体入口沿`scripts/check.ps1`。涉及API同步根OpenAPI及类型，涉及指南更新其结构化源。具体测试标签随实现文件登记到对应任务，不能只写“测试通过”而无范围。

<a id="152-固定验收样例集"></a>

### 15.2 固定验收样例集

| 样例 | 必须观察的结果 | 主责 |
| --- | --- | --- |
| F01 两种JSON布局 | 字段名/层级变化只改配置，原文、自定义文本、数值/布尔和媒体都可下游消费 | M1/M2 |
| F02 新剧本、空素材库 | 动态得到人物/场景/道具与主/变体需求，无事先手工建立实体/素材名单 | M2/M3/M4 |
| F03 一个主体、主图与两变体 | 两个实际变体请求均携带选定主图；变体候选次数不变成新服装设定 | M3/M4/M9 |
| F04 独立素材库 | 无剧本/配方也能上传、选已有、生成主图/变体；回到同一Asset库 | M9/M4 |
| F05 混合来源 | 部分目标用现有图/上传，其他目标生成；复用部分调用数为0 | M1/M4/M5 |
| F06 可见人与画外音 | 说话人可不在画面；缺失voiceover按配置，显式值/对白文字与时间保留 | M2/M5 |
| F07 名称和槽位 | 同名/多语言/两个服装、图片/视频/音频用途及输入重排均准确绑定 | M5/M6 |
| F08 长度/质量 | 建议质量提醒不硬阻断；真实上限仍生效；超限全文和准备UTF-8字节可见/可核对 | M6/M7 |
| F09 失败与恢复 | 一成功一失败只重试失败；主/辅助分开；有实际返回不显示成无内容 | M7 |
| F10 已有片段和新链交付 | 独立装配先可用；新产物替换输入后顺序、播放/导出仍正确 | M8/INT |

具体人名、造型和字段key均为夹具值，可换另一个项目验证，不能变成硬编码业务默认。缺真实目标时保留V-real待验状态，不拿外部模型替身生成的文件冒充真实模型产物。
