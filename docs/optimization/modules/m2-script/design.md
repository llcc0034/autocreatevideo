## 6. M2 剧本生成与结构化

<a id="61-背景需求与产出"></a>

### 6.1 背景、需求与产出

剧本产生时已能确定角色、场景、道具和造型变化，应在这一阶段形成下游可用声明。用户可以从创意生成新剧本，也可以把已有JSON/文本导入结构化。产出必须同时保留原文、所选结构化结果、自定义字段及实体/变体/逐镜声明；不以旧固定标记格式作为唯一协议。

输入：创意/已有剧本、输出结构版本、生成要求及执行实例。输出：原始返回、结构化候选/采用修订、声明key和逐镜数据。未知信息可在“创意生成”中按规则设计；“已有文本结构化”不得把自由扩写伪装为原文事实。

<a id="62-实现方式"></a>

### 6.2 实现方式

- 复用原文本队列、实例/Profile、候选与修订链；请求由`script_semantic_requests.py`消费确切输出合同，`script_semantics.py`及共用结构解析/映射负责字段含义、必填和结构说明，`script_revision_structures.py`保存/读取唯一结构化详情。不再拼固定人物/英文字段清单；旧声明模块的残留清理归M2-08，分镜实际writer按M5实现。
- 结构化JSON直接解析；自由文本调用既有AI结构化能力，显示原文与候选并按配置处理。AI调用由正式操作触发，预览不调用。
- 用配置映射连接业务语义：实体key/类型/名称、共同身份、主图设定、变体key/差异、集镜坐标、动作/机位/时间、场景/可见对象/发言人/素材使用。可无变体、无对白；有引用才检查对应关系。
- 对白正文保持原语言，不因参考名称改名而替换；未标明画外音时按明确配置默认普通对白，显式画外音保留。主观完整度显示建议，不强制每镜都有所有创作字段。
- 2026-09-30采用语义确认（CR-M2-METADATA-01方案1）：采用只更新本轮剧本修订及项目母稿，项目标题/梗概保持不变；不要求候选包含这两个字段，也不按自定义字段名猜测回写。候选内的标题等自定义字段仍保存、可供下游显式引用。可配置项目资料映射回写（方案2）延期，后续有需要再确认开发，不纳入本轮任务。
