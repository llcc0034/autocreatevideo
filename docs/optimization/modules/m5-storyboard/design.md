## 9. M5 分镜与素材引用

<a id="91-背景需求与产出"></a>

### 9.1 背景、需求与产出

同一实体可以有不同服装、不同视角及图片/视频/音频引用，必须知道本镜用哪一个。说话人不等于可见人物，参考素材的身份/用途也不能靠提示词译名反推。现有只读预检要进入真正的唯一分镜写入链。

输入：所选剧本修订、实体/设定声明映射、已有或本轮生成的可选素材。输出：集/镜头、显式场景/可见对象/发言人、逐次使用标识、准确的素材版本/用途/顺序。M5不生成图片，也不拼模型提示词；模型槽位编号由M6根据最终输入分配。

<a id="92-实现方式"></a>

### 9.2 实现方式

- `script_storyboard_plan.py`的关系预检读取M1语义映射；`production_storyboard_materialization.py`成为原人工/配方入口共用的唯一writer，不同时保留旧名字扫描逻辑。
- `Shot`关系区分主场景、可见人物、道具、对白发言者；逐次使用关系保存设定修订、用途、来源模式、确切素材版本及顺序，不能把当前`Shot.characters`全部等同可见人物。
- 关系预检分两层：哪些输入字段代表关系可配置；关系存在、实体归属、版本和引用完整性由通用代码保证。缺可选关系不阻断，有明确关系但找不到对象则指出路径，不能关闭校验来猜。
- 逐镜可按配方来源自动选本次结果，或允许用户从库内/本地上传明确改选。改选只影响本次镜头/用途，不暗改Bible主图。无需Bible的独立参考素材也可以加入。
- 批量选择是“为一组镜头的指定用途选素材”，不是已有字段正文批审；提交前列受影响镜头、原值、新值和冲突。每镜事务更新，结果逐镜回执，不悄悄跳过冲突。
