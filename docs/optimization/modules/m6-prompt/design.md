## 10. M6 提示词生成与组装

<a id="101-背景需求与产出"></a>

### 10.1 背景、需求与产出

图中已承载外观信息，视频提示词应通过引用名准确指向素材，重点描述动作、交互、构图、运镜、时间、对白和声音。不能在辅助输入和最终模板里重复注入Bible外观/静态锚点；也不能只显示某个两千字字段，却隐藏组装后超限全文。

输入：M5确切素材绑定、动态镜头事实、原对白、所选Profile/字段生成配置。输出：生成字段修订、采用/选择、名称与素材/真实槽位对应表、最终完整提示词和分项长度、实际准备字节数。图片生成仍使用M3的锚点，不受本模块视频精简规则误伤。

<a id="102-实现方式"></a>

### 10.2 实现方式

- **通用输入字段辅助结果（2026-10-18，已完成）**：字段定义负责类型，策略规则负责生成/翻译、原文及附加资料、最终字段/逐单元贡献、标签/顺序/通道；执行实例明确辅助模型，配方提供本次来源和采用方式。使用策略的文本、图像、视频入口共用准备/候选/采用/编译，不再按业务 operation 或 H3 三个贡献位置限制完整字段辅助生成。`final` 结果直接属于本条规则；`projection.output` 可作为服务端确定性原文，不是可注入输入。已有 `contribution` 保留其模板插入语义，不能隐含聚合多个单元或依赖另一字段未采用结果。附加结构路径与主要文本来源独立；素材、运行参数、人工完整提示词及可信系统约束不由此能力改写。后端57项、前端相关测试及构建通过，新策略v12/执行v15实际完成辅助生成→采用→六段冻结→视频Smoke成功；其他业务类型以隔离测试覆盖，不宣称所有外部模型都已实测。详见[本轮记录](../../records/m6-prompt/2026-10-18.md)。
- 在现有`prompt_profile_compiler.py`、来源投影器、`execution_preparation_fields.py`等入口实现同源装配；预览和真正提交调用同一个编译器，不做仅页面过滤版“精简提示词”。
- 先冻结有序素材使用清单，再由目标适配映射生成`<Picture n>`等真实端口标记；标记语法来自目标配置，不把H3格式硬编码为全平台规范。
- 辅助生成使用稳定使用标识/受保护引用名及动态事实。回复中的标识按确切映射恢复可读名称/模型标记，不对自由正文做全局姓名替换。同名素材在本次输入集合明确消歧，不强制英文。
- 输入投影不提供Bible外观、参考图生成prompt、`prompt_hint`或重复保留分析；最终仅集中说明一次名称→真实输入关系。不得用正则删人工作品中的外观句子冒充源头优化。
- 复用现有已保存正文、单镜一键/多镜批审、同镜版本、失败原文和全文超限展示；辅助任务配置位置在Profile字段规则+所选执行实例，页面提供明确跳转，不新建隐蔽任务配置。
- 字段长度与最终通道长度分别计数，采用合同规定的字符口径；完整准备按**写入时实际UTF-8序列化字节**计数，中文字符与字节不能混算。长度上限/质量建议与实际目标硬限制分开。
