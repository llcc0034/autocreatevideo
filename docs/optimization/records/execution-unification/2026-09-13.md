#### 实施顺序与验收条件（已获授权，按六步检查点推进）

1. 盘点当前受控来源和字段用途，明确项目事实、本次输入、受审输出、字段默认值与投影输出的所有权；以同一版本化合同提供目录和中文说明，不在前端另建映射表，不要求手写Key。

4. 冻结输入可查来源页面/对象/记录/修订或摘要、是否人工修改、采用值、目标字段、最终核心参数和实际system/user提示词；准备保存与查看均不调用模型。重新读取来源是明确动作，不能重写已冻结请求或自动重跑已完成任务。
5. 以“梗概+视觉风格”验收：选择精确策略后无需手动再建两条同名接线；创建准备能预览确定项目的两项内容；允许中文、英文与混合输入，实际语言处理遵循策略；最终提示词不额外带完整剧本/Bible或重复附带未声明上下文。独立Smoke能明确填写测试输入，不伪造项目上下文。
6. 覆盖同源多字段、不同来源同名、辅助生成/翻译、工作流端口、多候选结果、错误保留输入、版本变更和桌面/窄屏；三入口复用同一解析与冻结合同。同步正式文档、帮助源/生成指南与隔离回归；真实调用另行授权，不能将表单验收当作Smoke通过。

不做：任意JSONPath/表达式、自动猜项目/素材、自动模型摘要/翻译/重测、已发布合同原地修改、旧字段别名与双读双写。无需兼容旧实现；确需删除或重建不兼容配置时重新核对精确依赖和授权，保留应保留的审计事实，不把本次登记视为删除许可。

- 来源：已有受控上下文和已采用结果目录，以及权限/修订校验；第72–73批将读者合同持久化并扩展到24个位置，按精确版本派生、确认和编译。新对象／协议及更多类型仍需已实现的读取能力，新增选项说明或同名Key不等于新增读取能力。
- 输出：BusinessOutputVersion已支持visual_rules.v2三项业务字段的格式、最多4层JSON对象／固定数组位置、色彩允许值及质量建议，实例精确引用并进入运行合同；第80批核对了固定数组响应到原worker／审核／下游的隔离链路。影视规则／剧本等仍由实际业务解析器校验，ComfyUI核对冻结节点、类型和真实文件；新业务字段／类型及跨协议消费仍是缺口，不能把三项响应位置配置当作这些功能已经完成。
- 术语：提示词的`positive_prompt`/`system_instruction`等输出通道，是发给模型的内容去向；本节业务输出指模型/工作流返回并经平台解析的结果，二者不可混同。

<a id="目标范围与唯一职责"></a>

#### 目标范围与唯一职责

目标链路：**来源注册/选值 → 输入映射与请求 → 输出合同 → 解析与校验 → 候选审核/采用 → 精确输出成为下游来源**。上游输出定义同时决定哪些内容可被引用，不让上下游各维护一份相同字段结构；定义/配置版本与每次产生的实际值必须分离。

| 范围 | 页面应支持和解释的内容 | 权威职责与边界 |
| --- | --- | --- |
| 来源注册 | 名称、说明、稳定标识、值类型/结构、作用域、对应业务对象/受支持字段、读取方式、权限、修订依据和空值含义；提供合法对象上的取值预览 | 管理员通过受控选项定义新来源，来源标识按统一规则生成/校验；普通使用者选来源与具体对象，不写任意JSONPath/SQL/脚本。新定义仍须由现有或明确新增的读取适配器实现 |
| 输出定义 | 名称、业务含义、文本/结构化数据/媒体类型、字段、单位、枚举、必填/可空、数量、结构版本及校验规则 | 提示模型的输出要求、结果验证和可引用字段必须消费同一份版本化合同；实例引用精确合同，不能另抄一份Schema |
| 输出解析映射 | 将已声明响应字段或工作流输出节点映射为业务输出；显示原始响应与解析结果的对应位置及不支持的映射 | 复用驱动/业务适配器/Projector各自正式能力，不混为同一层；复杂嵌套、数组或新协议只有解析能力真实支持后才能配置，不承诺任何JSON都可无代码接入 |
| 保存与审核 | 声明结果所属项目/运行/步骤/对象、现有产物或内容修订的保存位置，以及作为候选、审核、采用的条件；展示预期与实际不符的具体项 | 原始响应、解析候选、人工修正和已采用结果分别保留来源，复用既有产物/内容版本/决定，不创建第二套结果库。校验通过不等于已采用；输出也不自动复制到素材库 |
| 输出作为来源 | 对允许引用的字段提供“上游步骤→明确已审核/已采用结果→具体字段/产物”选项、内容预览和类型检查 | 来源目录由输出定义及可引用规则派生，实际选择保留任务、候选/产物、审核/采用决定、版本和摘要；下游只配置使用关系，不再定义同一结构 |
| 生命周期与透明度 | 来源/输出定义的草稿、校验、发布、后继版本、停用、引用影响及样例验证；查看读取方、写入方和实际输入输出关系 | 修改须显式版本化并校验引用，不重写已发布定义/历史结果，不按latest偷偷换值；各页面共用一个权威目录和合同，精确存储模型/API在实施设计时确认 |

**支持边界**：在已支持对象/字段上组合一个新来源定义，与接入一个全新数据系统或读取协议不同；增加一个输出名称，与具备解析、存储、审核及下游消费能力也不同。页面必须明示“可配置”“需补适配器”“仅可查看”，不能让保存成功冒充端到端可执行。不得为了注册能力把底层认证、权限、媒体真实性或安全校验开放为可关闭选项。
