## OPT-LOCAL-RUNTIME-001 可配置、可插拔的本地文本模型运行时

<a id="当前现状"></a>

### 当前现状

- `local_qwen` Provider 当前只负责按 OpenAI-compatible HTTP 合同调用已存在的推理端点，不加载模型权重，也不安装、启动或守护 vLLM、Ollama、llama.cpp、Transformers 等运行时。
- Provider、模型版本与 Deployment 分别承担传输协议、不可变能力合同和精确运行实例职责；仅新增 `backend` 配置值不能证明后端依赖、模型文件、硬件容量或进程已经可用。
- 当前无代码操作口径仍是由运维侧先启动兼容服务，再在 Deployment 中登记端点并按 operation 完成真实 Smoke；不得把 Provider 启用或 Deployment 记录存在显示为模型已经部署。

<a id="目标方案"></a>

### 目标方案

1. 建立独立于 Django Web 与业务 worker 的 Python 文本推理运行时，对 AutoPrompt 稳定暴露统一的 OpenAI-compatible 接口；业务 Provider、PromptProfile 和 ProductionRecipe 不感知具体推理引擎。
2. 建立服务端受控的后端适配目录，允许按配置选择 Transformers、vLLM、llama.cpp 或 Ollama 等已支持实现；后端新增、停用和兼容范围由统一合同管理，不在业务阶段代码中增加模型专用分支。
3. 将后端类型、精确模型或受管权重版本、模型格式、设备、数据类型、量化方式、并发上限、上下文与输出上限、启动参数及监听范围纳入版本化、可审计配置；密钥和敏感地址继续使用受管凭据，不进入普通配置正文。
4. 由绑定 RuntimeHost 的受控运行代理负责预检、启动、停止、重启、健康检查、就绪检查、日志和异常退出回报；模型进程与 Django/业务 worker 隔离，避免重载、扩容或 OOM 连带影响业务服务。
5. 启动前校验后端依赖、模型格式与 hash、文件可访问性、设备能力和配置组合；缺失、不兼容、容量不足或退出必须失败关闭并保留明确原因，不自动换模型、降参或回退到其他后端。
6. 运行时就绪只证明服务可调用；正式路由仍须通过模型版本能力合同、Deployment 状态、按 operation 的新鲜真实 Smoke 以及后续容量证据门禁。

<a id="当前边界尚未启动"></a>

### 当前边界（尚未启动）

- 本项仅登记后续能力，不新增运行时服务、Schema、API、页面、启动脚本或依赖，也不下载模型、启动本地推理进程或执行外部 Smoke。
- 当前 `scripts/setup.ps1`、`scripts/restart.ps1` 与业务生产入口保持不变；在本项完整落地前，不把临时 Python 命令或本地脚本登记为第二套正式服务入口。
- 不以 Qwen、某个显卡型号或单一后端作为核心代码特例；首个实现可以缩小支持范围，但必须通过受控目录和兼容合同显式声明。

<a id="后续启动条件与验收"></a>

### 后续启动条件与验收

- 当需要由正式页面重复部署、切换或恢复本地文本模型，而外部手工运维已成为稳定阻碍时，再确认首批支持的模型格式、后端、RuntimeHost 和升级策略后进入实施。
- 用户可在正式页面选择受支持后端与精确模型版本，预检并启动实例；页面展示真实的准备中、就绪、失败、退出和停止状态及原因，不用配置已保存代替运行成功。
- 在不修改业务 Provider、PromptProfile 或 ProductionRecipe 代码的前提下，可以切换已注册后端；不兼容组合在保存或启动前由服务端拒绝。
- 进程、端口、模型 hash、配置版本、RuntimeHost、启动者、状态变化和日志关联可审计；停止、重启、崩溃恢复和并发冲突有幂等及权限测试。
- 运行时、Deployment、Smoke 与容量证据保持职责分离且相互引用，不形成第二套模型、路由或运行事实来源。
