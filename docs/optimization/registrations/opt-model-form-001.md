<a id="目标方案与范围"></a>

### 目标方案与范围

1. 复用服务端注册语义与现有Schema，提供同源字段目录：中文名称、技术Key、类型、单位、合法选项/范围、适用模态、所有权及空值含义。通用Key不接受自由拼写，前端不另建能力目录。
2. 枚举用选项，布尔用开关，数值用带单位/范围的数字框；不能把真实可变范围写死为几个尺寸。系统版本等由服务端生成且只读；名称/说明等真实业务文本仍可输入。
3. 分辨率提供“未声明/固定尺寸/允许范围”可视化编辑；固定尺寸一次输入宽高并生成同一份min/max，范围模式校验上下界和倍数可满足性。留空不等于0或无限，不能未经确认清空已有约束。
4. 首批覆盖完整media_constraints；随后盘点平台已支持的素材用途/配对、文本请求选项与质量建议，使用受控分组编辑。供应商扩展只有正式Schema支持后才出现，未知字段须显式诊断，不提供绕过校验的任意Key入口。
5. 模型与Projector消费同一语义定义，但职责不合并：模型声明能力边界，Projector配置端口/来源/更窄规则；显示最终生效约束及来源，冲突明确指出，不让用户手抄或默认覆盖。
6. 表单只读写原`specification`；完整JSON默认折叠、作为只读核对视图，不保留普通用户第二套自由写入口。发布版本保持不可变，修改走后继草稿；不增加历史别名、转换或双写。
7. 系统预算、调用次数与输出额度继续在系统设置，不借“模型参数表单化”重新引入模型/步骤额度配置。币种与金额填写的引导可在原系统资源编辑器收敛，不新设预算来源。

<a id="实施验收与不做事项"></a>

### 实施、验收与不做事项

- 顺序：后端字段目录/校验 → 共用控件与模型表单 → Projector语义选择/来源说明 → 删除通用参数JSON可写旁路 → OpenAPI、帮助源与生成指南、测试同步。
- 验收：创建/后继草稿全部通用字段不用写JSON；固定/范围/未声明往返无丢失；缺目录/未知Key/非法范围不伪装成功；模型与节点冲突可定位；已发布源版本和历史冻结请求不变。
- 覆盖权限、保存失败保留输入、版本冲突、桌面/窄屏/键盘、服务端拒绝伪造字段与重复来源；不以JSON格式正确替代真实模型能力。
- 本项不包含自动推断模型能力、任意新执行语义、真实Smoke或批量清理。无法直接使用的旧配置只在另行核定范围后重建/删除，不为保住历史增加兼容代码。
- 已有目录收敛成果仍属OPT-SETTINGS-001；本项补齐剩余合同表单，不重复关闭/重开原条目。
